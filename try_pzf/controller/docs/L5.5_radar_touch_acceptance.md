# L5.5 雷达与基座触摸接入

状态：源码已接入；尚未完成完整构建、烧录和硬件验收。

## 范围

- controller 新增 radar_driver / radar_ld6002 / touch_driver / touch_service。
- 新增 main/peripheral_inputs.c/.h；main 初始化与 CMake 接线。
- base/head/voice 未修改；不引入聚合 BSP、雷达占位解析器或第二个 UART 读取者。
- 不改音频、唤醒、舵机、分区、HTTP 超时；不接专注/LCD/关机联动。

## 生效配置

- 雷达：按 base/sdkconfig 迁移 UART3，115200，ESP TX=GPIO7、RX=GPIO1。
  旧 common/pin_config.h 雷达方向与此相反，本驱动不使用那两个宏。
- 解析：沿用 base 实际启用的 LD6002 模块，SOF=0x01，大端头字段，
  XOR-NOT 校验；支持原 reader 的距离消息 0x0A16 及项目配置的 0x0A18。
- 触摸：TTP A/B/C/D=GPIO9/22/10/23，高电平有效、下拉输入，扫描 10ms。
  消抖沿用驱动 3 次确认；长按 600ms、双击窗口 300ms。
- 新组件 Kconfig 默认开启。此次不手改 sdkconfig；下一次 IDF 构建会生成
  CONFIG_PROJECT_RADAR_* 与 CONFIG_LOCAL_TOUCH_ENABLE。
- 雷达任务栈 4096、优先级3；触摸任务栈2048、优先级4。启动失败各自记录并继续。

## 实机验证（只构建/烧录 controller，不需要 head）

1. 在 VSCode 打开 controller 工程，正常 Build、Flash、Monitor，不做 fullclean。
2. 启动检查：
   - Radar UART initialized (port=3, baud=115200, tx=7, rx=1)
   - LD6002 reader initialized (SOF=0x01, BE fields, XOR-NOT)
   - Local touch ready: A=9 B=22 C=10 D=23
3. 雷达每10秒输出 Radar summary：
   - rx_bytes 持续增加只证明收到字节，frames 增加才证明完整帧校验通过。
   - presence_valid=1 后，人在检测区进入/离开，应看到 present 的对应变化。
   - heart/breath/range 只有各自 valid 标志为1才是收到的读数；这是雷达输出，
     不是经过医疗标定的数据。无字段上报不伪造默认成功值。
   - frames=0 的警告表示协议/硬件尚未确认：检查供电、TX/RX与模块类型。
4. 四路触摸逐个短按、快速双击、长按超过600ms：
   - 日志 Touch A/B/C/D single/double/long/release，应与实际按键匹配。
   - 双击后不应再额外出现一次 single；空闲不应持续误触发。
   - 本批只输出事件与更新 device_state.key。长按不会关机、不会切断ESP-Hosted；
     不要求LCD翻页、模式切换或自动动作。
5. 回归：重复唤醒/播报后再唤醒、灯带控制、机械臂摇头/跳舞。
   看有无 panic、OPUS -2、动作失败；雷达串口未接时也不能拖垮这些功能。
