## 实现规则

### 采样、缓存与接口

- 独立低优先级任务，每秒执行一批 **8 次连续 ADC 读取的均值**。不是每 20 ms 读 ADC，也不保证抑制工频照明闪烁。
- 正常运行按实际经过的约 2 秒窗口汇总成功批次，再做 EMA，系数 0.5。失败不是零照度；空窗口不重复发布、不刷新时间。第一次成功、过期后恢复成功，直接用新读数初始化。
- 查询只复制缓存，不读 ADC，不刷新样本时间。LED 与 HTTP 读同一缓存；没有新增第二条事件发布/订阅更新链路。
- `last_ok_ms` 是已纳入缓存的最后成功批次时间。`age_ms <= 10000` 才新鲜；两者都用 controller 单调运行时间，不是日期或 Unix 时间。
- 新鲜时 `/api/ambient` 返回 HTTP 200，含 `ok`、数值 `level`、`lux`、`sampled_at_ms`、`age_ms`。短暂采样失败仍可使用未过期缓存。
- 没有有效样本或已经过期：HTTP 503，正文**不含 `level`**。真实 `lux=0`、`level=0` 仍是有效黑暗，不等于读数失败。
- `lux` 是既有 ADC 换算的估计值，未做照度计校准。ADC 返回合法值也不能证明传感器物理连接正常。

分档保持 controller 原阈值，统一位于 `ambient_service`：

| 环境档位 | 估计照度范围 | 自动谷值 / 峰值（原始亮度） |
| --- | --- | --- |
| 0 | 0–20 lux | 4 / 12 |
| 1 | >20–100 lux | 5 / 16 |
| 2 | >100–500 lux | 6 / 20 |
| 3 | >500–1000 lux | 8 / 25 |
| 4 | >1000 lux | 10 / 30 |

### 呼吸与优先级

- 暗处整体更柔和，亮处整体更亮。表中数值是**首测参数**，范围始终不超过原始亮度上限 30，不是百分比。
- 保留 3 秒呼吸周期和既有 20 ms 更新节拍。峰谷用同一个约 400 ms 时间常数平滑移动，不重置呼吸相位；长调度空窗后，单次包络推进最多按 100 ms 计算。
- 自动目标峰谷差至少 4；这不是视觉效果保证。从手动低亮度恢复自动时，过渡中的峰谷差可以暂时小于 4。
- 无新鲜光感时自动目标平滑回退到旧范围 5 / 30，不伪造黑暗档。
- 呼吸期间显式设置亮度，包括语音直接调用的 `led_service_set_brightness()`、档位设置、加减亮度，进入手动峰值覆盖。不能漏掉直接设置接口，否则语音调亮度会在下一帧被自动覆盖。
- 降低手动峰值后，输出立即不超过新上限；原始亮度 0–3 不被最小振幅规则强行抬亮。谷值不高于峰值，必要时退化成常亮或黑色。档位 0 保持原有关灯行为。
- 重新选择呼吸效果（包括已经在呼吸时再选一次）清除手动覆盖，恢复自动。`turn_on()` 不设置手动覆盖；陪伴模式原有 `turn_on(15)` 不会把自动峰值锁死在 15。
- 光感任务只更新缓存，不发开灯/切模式命令。关灯和非呼吸模式不因光感变化被重新点亮或改亮度。
- 请求亮度与渲染亮度仍是不同口径：陪伴入口保存的请求值可能是 15，而自动峰值可到 30。本批不重写既有控制状态/UI；`Breath` 日志的 `target` / `applied` 才是呼吸峰谷。

头灯单击的“暗处补光、更亮”与底座呼吸的“暗处氛围、更柔和”用途不同，方向不同是设计意图。head 源码不变，但其 `/api/ambient` 输入已变为平滑缓存，需回归单击与失败回退。

本批不做自照补偿、不增加固定驻留时间或额外迟滞、不放开 30 上限。阈值附近是否来回跳档，留待实测后判断。

## 下一次上板验收（只更新 controller，COM6）

1. 在 ESP-IDF 环境打开本工程 `controller`，编译并烧录 COM6。head 不需要因本批改动重新烧录，Docker 不需要重建。若编译失败，先修编译诊断，不用旧 bin 代替本批源码。
2. 串口应出现 `Ambient service started` 和 `Ambient light: ... lux (avg ..., level ...)`。第一条只说明任务创建；后者及样本年龄才用于观察读数更新。
3. 使用串口当前显示的 **controller IP** 查询接口（不是 head IP）：

   ```powershell
   $controllerIp = '填入当前基座IP'
   Invoke-RestMethod -Uri "http://$controllerIp/api/ambient" -TimeoutSec 5
   ```

   正常应有 `lux`、数值 `level`、较小的 `age_ms`。连续查询不能让 `sampled_at_ms` 自己更新；它只随成功采样更新。
4. 开启陪伴模式/呼吸灯。遮挡光敏、移开遮挡、改变外部光源，每次等缓存与包络收敛；观察 `Breath state=auto`、`target`、`applied`，应朝上表对应范围移动，呼吸相位不中途重启。亮环境自动目标能超过入口值 15。
5. 呼吸中用既有底座亮度语令逐步降低亮度，确认 `state=manual`、峰值不超过请求上限；特别测试零值和低值。桥接百分比会按既有换算转成 0–30 原始值，不能把“3%”当成原始值 3。
6. 手动覆盖后改变环境光，手动峰值仍保持；再次选择呼吸，恢复 `auto`。关灯后改变环境光并等至少 10 秒，不得自动亮起；常亮和彩虹效果也应维持各自原逻辑。
7. 采样失败/停止更新的受控测试：未过期时保留读数，超过 10 秒后接口 503 且无 `level`，呼吸使用 fallback。恢复成功后重新获得新鲜值。**不要带电拔插传感器来制造错误**；本批未添加远程故障注入接口。没有安全注入条件时记录此项未测，不能凭断开模拟线后读到 0 就当作通过。
8. 回归头灯单击（新鲜读数正常补光；接口失败时保留原手动回退）、退出陪伴模式、语音对话、机械臂点头与摄像头并用。观察持续 5–10 分钟是否出现重启、语音明显变慢或灯效停顿；目前没有这些板上数据。

### 自照与临界档位观察

外部照明、颜色、传感器位置保持不变，分别关灯、底座常亮原始值 30，等读数收敛后比较 `lux`。差值仅是该条件下的灯自身贡献，不是“扣除后的环境照度”或完整耦合增益，不进分档算法。

再开呼吸，在阈值附近观察读数距最近阈值的余量、波动幅度及 `level` 是否反复切换。不能用固定“差值小于 20 lux”就判定无影响；不为此另加计数器。
