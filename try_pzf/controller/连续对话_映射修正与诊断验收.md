# 连续对话映射修正与诊断验收

## 修改范围

仅 controller：唤醒引擎使用已有 active 注册表按语言和命令 ID 解析短语，不再上传 MultiNet 音素串；无匹配时告警并忽略该次唤醒。

audio_bridge 和 xiaozhi_manager 提供同步计数快照，主程序现有健康循环每 5 秒打印两行。原有 Heap 日志仍每 10 秒输出。没有新增任务，没有修改监听时序、播报期间上行策略、既有重连策略、head 或 Docker。后续 C3 试验另外修改了 managed 库的音频 binary 发送，见文末。

诊断不记录录音或识别文本，仅记录计数和 PCM16 最大绝对幅值。计数为开机累计，日志 delta 是相邻采样间差值；peak 为本采样间隔最大值。任务调度会影响实际采样间隔。多个门控可以同时拦截，拦截次数不能简单求和当成丢帧总数。

## 生效与测试

本次没有执行编译或烧录。用户已于 2026-10-16 确认语音基座板端口为 COM6；用户准备测试时自行构建 controller 并烧录基座板。不要把 controller 烧到 head。

1. 等待 Connected to server 和 Microphone capture started。
2. 说 focus，唤醒日志应显示 phrase='focus'，不再是 FbKcS。中文分支输出的是注册的拼音原文，不承诺自动转中文汉字。
3. 等问候完整结束，再说“打开底座灯光”，随后说“关闭底座灯光”。
4. 保存从唤醒前到第二句话后约 30 秒的完整日志，包含 MIC_DIAG、UPLINK_DIAG、TTS 和 STT。
5. 先在摄像头传输关闭时测一次，再开摄像头做同样对照。不要同时改变热点、音量等其他变量。

## 日志判读

- MIC_DIAG：read 为读 I2S 的调用数，rx 为完整采集帧；rx_err/partial 为读取失败或短帧；peak 表示 PCM16 幅值，不是语音识别置信度。enc_try/enc/enc_err/enc_empty 分别表示编码尝试、有效编码帧、编码错误和空输出。
- UPLINK_DIAG：cb 为上传回调次数；block_state/block_tts/block_local 分别表示状态不允许、TTS 暂停和本地音频占用。
- send_try/send_ok/send_fail 为本地上传 API 尝试、成功、失败；last_send_fail 保存最近一次失败码，之后成功也不清除，初始 ESP_OK 表示尚无失败记录。API 成功不等于服务端收到或识别成功。
- resume_try/resume_ok/resume_fail 只统计播报结束后的 listen/start，不是所有监听请求；last_resume_fail 口径同上。
- total_send_try 与 total_send_done 是累计尝试数和累计返回数。短暂差 1 可能只是正在调用；若多次采样都不变且差值持续存在，提示上传调用可能停滞，不能单凭一次采样判断卡死。
- 采集持续有帧、编码没有推进：检查编码前的 PCM 消费回调及编码调用；采集也不推进：检查采集任务或其前一次调用是否阻塞。
- 编码和 cb 推进但 send_try 不推进：查看门控计数。send_fail 增长则查看具体错误码。send_ok 增长仍无 STT，继续查音频内容、传输与服务端处理，不能直接定为服务端故障。
- 空闲未唤醒时 block_state 增长、播报时 block_tts 增长是当前设计行为；本地提醒播放时 block_local 增长也是正常行为。

映射修正只纠正唤醒文本，不宣称已解决连续对话失效；实际断点需以上述数据确认。

## C3 音频有限等待试验

- 仅 esp_xiaozhi_websocket.c 的 binary 发送采用 XIAOZHI_AUDIO_SEND_TIMEOUT_MS=10000。首测曾用 3000，实机出现多次约 3 秒的 poll/write 超时，现放宽为 10 秒做对照；这可能延长一次失败时的采集停顿，不保证解决链路拥堵。文本发送不变，没有增加音频重发。
- 返回长度必须等于请求长度；负数、零或短写进入原有失败通知路径。失败日志先于通知回调输出，带 sent/requested/elapsed_ms/timeout_ms。成功耗时达到 1000ms 时输出 slow 警告，正常帧不逐帧打印。
- 新增 esp_timer 直接组件依赖以匹配所用计时 API；未修改 dependencies.lock、sdkconfig 或底层 esp_websocket_client。
- UPLINK_DIAG 的 inflight_ms 表示快照时未记录返回的上传调用年龄。调用前写入起点，返回后清零，起点读写由诊断锁保护。若麦克风任务被停止／强删，清除起点并单独累计 total_send_cancelled，不伪报为成功或传输失败。判断累计未完成量时需要扣除取消数。
- 10000ms 不是端到端硬截止时间：等锁、分段写入、TLS 处理、事件投递和错误收尾均可能影响总耗时。不能单凭返回时间定位底层阶段。
