# L5.6 底座 LCD 验收

只编译/烧录 `controller` 工程，烧到当前运行 controller 的底座板。
不需要连接 head。不要烧录旧 base 工程；不需要 fullclean。

## 本批显示范围

- 待机：`IDLE / --:-- / READY`。
- 专注：`FOCUS / MM:SS / RUNNING`；对话期间为 `PAUSED`。
- 陪伴：`COMPANION / --:-- / ACTIVE`。
- 专注结束：`IDLE / 00:00 / COMPLETE`。
- 仅显示已有模式状态；不另起计时器，不改变语音通道关闭规则。
- 不实现表情、触摸翻页、光感/雷达显示或自动灯光/机械臂联动。

## 启动检查

顺序应为 OPUS startup prepared → 模式 ready → LCD 初始化 → LCD UI started。

关注以下日志：

```text
OPUS decoder prepared at startup (internal RAM, retained for TTS)
Initializing LCD driver (160x60 logical, 60x160 physical) BL_gpio=51
[SPI_INIT] bus=... mosi=36 sclk=50 cs=34 dc=49 speed=4000000
LCD memory [before allocate]: caps=...
LCD memory [after allocate]: caps=...
LCD driver initialized successfully: first black frame completed, buffers=38400 B
LCD status UI started: 1 s snapshot, no independent countdown
```

实际引脚：BL51 / SCLK50 / MOSI36 / DC49 / CS34，SPI2，4 MHz。
逻辑 160×60 软件旋转到物理 60×160，X 偏移 34，RGB565。
逻辑与物理缓冲各 19200 字节，init 动态分配内部 DMA 内存。
没有静态整帧 DMA 数组。两种内存日志口径不做减法预测。

## 功能检查

PC 必须连接设备所在热点。`$ctl` 换成本次启动 Got IP 的实际地址，
不能照抄旧 IP。以下为 Windows PowerShell：

```powershell
$ctl = "http://<本次-controller-IP>"
curl.exe --max-time 8 -i "$ctl/api/device/info"
'{}' | curl.exe --max-time 8 -i -H "Content-Type: application/json" --data-binary '@-' "$ctl/api/chat/end"
curl.exe --max-time 8 -i "$ctl/api/mode"
```

`/api/chat/end` 必须 POST（`--data-binary` 自动使用 POST）。其旧 handler 的
200 不证明关闭副作用已完成；等待 `/api/mode` 的 `voice_active=false`。
确认后开启一分钟专注：

```powershell
'{"mode":"focus","duration":1}' | curl.exe --max-time 8 -i -H "Content-Type: application/json" --data-binary '@-' "$ctl/api/mode"
curl.exe --max-time 8 -i "$ctl/api/mode"
Start-Sleep -Seconds 15
curl.exe --max-time 8 -i "$ctl/api/mode"
```

屏幕应约从 01:00 递减到 00:45，与接口 remaining_sec 差不超过一次刷新周期。
唤醒并对话后应变 PAUSED，期间剩余时间停止。播报结束仍在监听时继续暂停是
现有语义，不是 LCD 故障。结束对话并确认 voice_active=false 后恢复递减。
到期显示 COMPLETE；后续显式切 idle 清除完成标记。

```powershell
'{"mode":"companion"}' | curl.exe --max-time 8 -i -H "Content-Type: application/json" --data-binary '@-' "$ctl/api/mode"
'{"mode":"idle"}' | curl.exe --max-time 8 -i -H "Content-Type: application/json" --data-binary '@-' "$ctl/api/mode"
```

## 收口判据（需实机，不以语法检查代替）

1. 仅 controller 构建成功，分区/sdkconfig 无手动改动，head 不重刷。
2. 首帧清黑完成后才开背光；无启动白屏闪现。
3. 字体方向、完整边界正确，不镜像、不越界、不撕裂。
4. idle/focus/companion 与接口状态一致。
5. 专注剩余时间递减且与接口对得上。
6. 对话显示 PAUSED；结束对话后显示 RUNNING 并恢复递减。
7. 到期显示 00:00 / COMPLETE；显式 idle 后 READY。
8. 连续语音播报有声，无 OPUS -2、panic 或重启；解码器仍为启动期常驻。
9. 灯带和机械臂回归正常，不因显示刷新丢动作或卡语音。
10. LCD 内存分配/初始化失败仅降级，不中止其他模块。
11. 代码保证 CASET/RASET 失败不继续 RAMWR；提交失败停止刷新。
12. 完成等待最多 500 ms；超时停刷，无法确认 DMA 完成则保留缓冲/IO/信号量，
    日志为 `LCD shutdown incomplete` / `LCD cleanup deferred`，不得继续改写或释放。

11/12 的故障行为已静态核对，但未做实机故障注入。
不要通过带电拔插屏幕来模拟故障。
