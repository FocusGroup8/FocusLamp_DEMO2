# 智慧语音

## 1. 在线大模型对话
- 支持用户与大模型进行流畅对话

## 2. 自定义唤醒词
- 支持将唤醒词换成与产品相关的（如Focus）
- 当前：通过指定系统语言，中文英文二选一
- 未来：依赖云端能力，支持多语言交互

## 3. 优化小智对话的稳定性
- 降低唤醒误触发率、误识别中断对话
  - 误触发率调整：通过调整 esp-sr 组件中的检测阈值配置实现
  - 误识别中断调整：通过调整 esp-sr 中的 VAD 检测阈值及最小语音持续实践实现

## 4. 长语令任务拆解
- 支持用户输入长语令任务后拆解为模式化任务并执行  
  例：用户输入“我接下来的两个小时需要专心写论文了” → 映射为“开启2h的专注模式任务”
- AI拆解任务，基于用户的任务诉求拆解为执行步骤  
  例：用户输入“我准备写一篇论文” → 映射为“1. 行业洞察；2. 梳理大纲；3. 查询相关专业知识...”
- 实现机制
  - **指令拆解与执行**：通过离线或在线语音识别模型对指令中的关键字、变量等进行解析，支持将长语令拆解为 MCP 预定的多段指令
  - **任务拆解与显示**：通过在线语音识别模型识别用户输入，通过系统提示词对任务类型进行识别，将原始任务相关内容拆解为任务名称及相应时长

## 5. 固定指令控制

### 5.1 任务控制
- **固定指令创建/终止任务**
  - “开启30分钟的专注模式” → 创建30分钟专注模式任务并启动倒计时
  - “结束任务/结束XX任务” → 结束当前任务；若当前无进行中任务，则提醒用户“当前没有进行中的任务，请创建新任务后再试试吧~”
- **指令槽位提取**：“开启**专注模式”指令识别槽位：“开启/关闭”-“时间（分钟）”-“**模式/任务”
- **模式管理器+定时器**：根据解析到的时间与模式变量，创建相应时间与模式的任务
- **小屏幕状态显示**：将创建的任务变量映射到屏幕，遵循屏幕显示规范
- **查询当前任务队列状态**：返回有或无，若有则直接结束任务，若无则执行 TTS 播报预设语音
- **TTS 播报查询结果**：若当前无进行中任务，提醒用户“当前没有进行中的任务，请创建新任务后再试试吧~”

### 5.2 灯光控制
- **固定指令与映射**
  - “开灯” → 启动灯头灯光
  - “开启底座灯光” → 启动底座灯光
  - “关灯” → 关闭全部灯光
  - “关闭灯头灯光” → 关闭灯头灯光
  - “太亮了调暗一些” → 灯光亮度下调（按可取值范围均匀变化）
  - “太暗了调亮一些” → 灯光亮度上调（按可取值范围均匀变化）
- **映射规则细节**
  - a. 当无任何灯光时，开灯仅开灯头主灯光
  - b. 支持用户指定灯光的开启与关闭
  - c. 不管灯光亮了几个，关灯指令映射的是关闭全部灯光
  - d. 亮度调节若已达到上限/下限，告知用户当前亮度已调整为最高/最低
  - e. 默认灯光在每次启动设备时重置，根据感光模块的环境光识别结果，调整为一个适合的亮度（具体逻辑结合可行性定义）
  - f. 支持多轮对话：当识别到用户调节的亮度与感光模块反馈的护眼方案不一致时（如暗光环境下灯光也较暗，会伤眼睛；正常逻辑为环境光越亮台灯亮度调低，环境光越暗台灯亮度调高），语音告知用户当前灯光亮度存在伤眼风险，询问是否同意自动调节为护眼模式。用户回复“好的”则调节（自动调节为护眼模式/遵循感光模块推荐亮度），用户回复“不用了”则不执行调节
- **感光模块**
  - 上电后，感光模块返回当前环境光亮度
  - 默认灯光重置：每次启动设备时，根据感光模块的环境光识别结果渐变调整为一个适合的亮度
- **固定指令识别**
  - 开灯头灯/关灯：识别“开灯”指令后开启灯头灯；识别“关灯”指令后关闭所有灯光
  - 开关指定部分灯光：识别“开启**灯光”指令后开启指定位置灯光；识别“关闭**灯光”指令后关闭指定位置灯光
  - 灯光亮度调节：识别“调亮”指令后灯光亮度上调一个等级；识别“调暗”指令后灯光亮度下调一个等级
- **TTS 播报**
  - 亮度达到上限/下限时，告知用户“当前亮度已调整为最高/最低。”
  - 护眼提醒：当用户指令与感光模块反馈存在冲突时，语音告知“当前灯光亮度存在伤眼风险，是否同意灯光自动调节为护眼模式？”
- **护眼模式交互**：用户回复“好的”则调节为护眼模式（遵循感光模块识别结果），用户回复“不用了”则不执行调节

### 5.3 机械臂控制
- **固定指令**
  - “XX（唤醒词），你过来” → 灯头向用户方向伸展，若底盘支持移动则向用户靠近（需摄像头提供用户方向信息）
  - “好了，你回去吧” → 灯头回归原位（台灯需记录稳定状态坐标，指令映射用户交互前的坐标）
  - “XX（唤醒词），跳个舞吧” → 执行舞蹈动作（动作库需基于“跳舞”动作定义，构建能表达跳舞的轨迹，并支持持续拓展）
- **固定指令识别**：“XXX，你过来”，支持泛化表达如“XXX，你过来一下”“XXX，你靠近一点”“XXX，come on”
- **摄像头**：识别用户方向，返回用户相对设备的坐标，指引机械臂延展方向
- **毫米波雷达**：识别用户相对距离，返回用户相对设备的坐标，指引机械臂延展距离
- **机械臂状态记录**：实时记录当前灯头、机械臂、底座的坐标系，结合摄像头与毫米波雷达的返回值，实时计算运动轨迹

### 5.4 扬声器控制（唱歌/陪伴模式）
- **固定指令**：“XX（唤醒词），给我唱首歌吧” → 播放曲库中的歌曲，唱歌过程中结合节奏进行卡点运动（陪伴模式）
- **指令识别**：识别“XX（唤醒词），给我唱首歌吧”及泛化指令，触发歌曲播放
- **歌曲频谱识别**：基于曲库歌曲进行律动识别，输出节拍时间戳、强弱
- **机械臂卡点**：根据节拍时间戳、强弱映射机械臂的运动频率和幅度

## 6. TTS 内容输出

### 6.1 基础能力
- 集成 esp_xiaozhi 组件，配置音频回调、事件回调、音频格式参数
- 音频格式配置：OPUS（低延迟），采样率16kHz，单声道，帧时长60ms
- I2S 扬声器驱动：配置I2S接口驱动单声道小功率扬声器播放TTS合成音频
- TTS 状态事件监听：监听 start/stop/sentence_start 事件，用于状态管理和界面显示
- 音频回调处理：实现 audio_callback 函数，将接收的TTS音频数据送入扬声器播放
- 优先级管理：建立 TTS 播报优先级队列（0-3级），高优先级播报可打断低优先级播报

### 6.2 预设文本转化语音（主动注入机制）
- 主动注入 API 封装：封装 `esp_xiaozhi_chat_send_text()` API，支持主动注入预设文本触发TTS播报
- MCP 工具注册：注册 `self.notification.speak` 工具，支持服务端推送预设文本触发TTS播报
- WebSocket 推送接收：接收服务端推送的 `tts_inject` 消息，解析 `text` 字段触发TTS播报
- prompt/固定指令注入：支持通过 prompt 或固定指令主动注入，触发对应预设回复的文本以语音形式传递
- 典型场景：基于摄像头识别结果触发TTS播报，例如视觉算法识别用户坐姿异常时，触发固定语音主动干预，引导用户改变坐姿（涉及 prompt/固定指令主动注入，将预设回复文本转化为语音）

### 6.3 预设语音资源库管理
- 整体策略：复用 LittleFS 文件管理系统，采用“预设语音 + 云端TTS实时合成”两种形式
- 本地音频资源存储：Flash 中存储预设音频文件（.ogg格式，相比 mp3 更便于解析）
- 坐姿提醒音频：存储“坐姿异常提醒”预设音频，例如“检测到您的坐姿不太标准，建议调整坐姿”
- 专注度提醒音频：存储“专注度下降提醒”预设音频，例如“您的专注度有所下降，要不要休息一下”
- 久坐提醒音频：存储“久坐提醒”预设音频，例如“您已经久坐40分钟了，建议活动一下”
- 云端TTS实时合成：对于动态内容（如任务名称、倒计时），采用云端TTS实时合成而非预设音频

### 6.4 MCP 协议 TTS 工具
- **play_tts 工具注册**：注册 `self.audio_speaker.play_tts`，支持播放预设文本语音，参数：text（文本）、preset_id（预设ID）
- **notification.speak 工具注册**：注册 `self.notification.speak`，支持主动向用户播报信息，参数：message（消息）、priority（优先级0-3）
- **camera.detect_and_speak 联动**：注册 `self.camera.detect_and_speak` 工具，支持视觉识别并语音播报结果
