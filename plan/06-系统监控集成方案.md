## 目标
集成 ESP-IDF 内置的资源监控工具，实现对音频系统运行期间 CPU、内存、任务等系统资源的实时监控与日志记录。

**承接上一步**：文档 `05-录播闭环测试方案.md` 完成了音频闭环测试验证规划，本文档添加系统资源监控能力，用于性能分析和问题诊断。

**当前状态**：本模块尚未实现。I2S 驱动层已完成验证，后续在录音/播放模块开发完成后，集成系统监控模块。以下为设计规划文档。

## 阶段流程

### 步骤1：ESP-IDF 系统监控工具调研

#### 1.1 可用的内置监控工具

ESP-IDF 提供以下内置资源监控功能：

| 工具/组件 | 功能 | 头文件 | 说明 |
|-----------|------|--------|------|
| `esp_heap_caps_get_info()` | 堆内存统计 | `esp_heap_caps.h` | 查询各类型内存（内部/SPIRAM）使用量 |
| `esp_task_wdt_info()` | 任务看门狗状态 | `esp_task_wdt.h` | 监控任务是否超时 |
| `vTaskList()` | FreeRTOS 任务列表 | `FreeRTOS.h` | 获取所有任务的状态和栈使用情况 |
| `vTaskGetRunTimeStats()` | 任务运行时间统计 | `FreeRTOS.h` | 各任务的 CPU 占用百分比 |
| `esp_psram_size()` / `esp_free_heap_size()` | 内存信息 | `esp_system.h` | PSRAM 大小和剩余堆空间 |
| `heap_caps_print_heap_info()` | 详细堆打印 | `esp_heap_caps.h` | 打印详细的内存分配块信息 |
| `perfmon` 组件 | 性能计数器 | - | 需在 menuconfig 中启用 |

#### 1.2 推荐使用的监控组合

针对音频系统的资源特点，推荐以下监控策略：

**基础监控（始终启用）**：
- 堆内存使用量（总堆 + SPIRAM）
- 音频相关任务的栈水位（Stack High Water Mark）
- I2S DMA 缓冲区状态

**高级监控（可选启用）**：
- 任务 CPU 占用率（需开启 CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS）
- 实时性能计数器（需启用 perfmon）

### 步骤2：监控模块设计

#### 2.1 模块接口

创建 `c:\Projects\Espressif_Projects\mipi_dsi\main\audio\system_monitor.h` 和 `system_monitor.c`：

```c
#pragma once

#include "esp_err.h"

/**
 * @brief Initialize system monitoring module
 *
 * Sets up periodic timer for automatic logging.
 * Must be called after audio system is initialized.
 *
 * @return ESP_OK on success
 */
esp_err_t sysmon_init(void);

/**
 * @brief Start periodic system status logging
 *
 * Logs memory and task info at specified interval.
 *
 * @param interval_sec  Logging interval in seconds (0 = one-shot, default 10)
 * @return ESP_OK on success
 */
esp_err_t sysmon_start(uint32_t interval_sec);

/**
 * @brief Stop periodic logging
 */
void sysmon_stop(void);

/**
 * @brief Print current system status (one-time)
 *
 * Outputs to ESP_LOGI with tag "SYSMON"
 */
void sysmon_print_status(void);

/**
 * @brief Get audio-specific metrics
 *
 * Returns statistics about the audio subsystem.
 */
typedef struct {
    size_t heap_before_audio;   /*!< Heap size before audio init */
    size_t heap_after_audio;    /*!< Heap size after audio init */
    size_t i2s_dma_buf_used;    /*!< I2S DMA buffer usage in bytes */
    uint32_t rec_duration_ms;   /*!< Total recording time in ms */
    uint32_t play_duration_ms;  /*!< Total playback time in ms */
} sysmon_audio_metrics_t;

void sysmon_get_audio_metrics(sysmon_audio_metrics_t *metrics);
```

### 步骤3：menuconfig 配置项

#### 3.1 启用运行时统计

需要在 menuconfig 中启用 FreeRTOS 运行时统计：

```
idf.py menuconfig
→ Component config
→ FreeRTOS
→ Enable Run Time Stats → y
→ Use clock cycle counter as run-time stats clock → y (如果支持)
→ Generate stats only when vTaskGetRunTimeStats() is called → y (节省CPU)
```

#### 3.2 新增 Kconfig 配置项

在 `Kconfig.projbuild` 中添加监控相关配置：

```kconfig
config EXAMPLE_ENABLE_SYSMON
    bool "Enable system resource monitor"
    default y
    depends on EXAMPLE_ENABLE_AUDIO
    help
        Enable real-time system resource monitoring during audio operations.
        Logs heap usage, task stack watermarks, and CPU utilization.

config EXAMPLE_SYSMON_INTERVAL_SEC
    int "Monitor log interval (seconds)"
    default 10
    range 1 3600
    depends on EXAMPLE_ENABLE_SYSMON
    help
        Interval between automatic system status logs.
        Set lower value for detailed debugging, higher value for production.

config EXAMPLE_SYSMON_PRINT_TASK_LIST
    bool "Print task list in monitor report"
    default y
    depends on EXAMPLE_ENABLE_SYSMON
    help
        Include FreeRTOS task list with stack high water marks.
        Increases log output but useful for debugging.
```

### 步骤4：实现要点

#### 4.1 定时器驱动日志

使用 esp_timer 创建周期性定时器触发日志输出：

```c
static esp_timer_handle_t s_mon_timer;

static void sysmon_timer_cb(void *arg)
{
    sysmon_print_status();
}

esp_err_t sysmon_start(uint32_t interval_sec)
{
    if (interval_sec == 0) {
        interval_sec = 10;
    }
    const esp_timer_create_args_t timer_cfg = {
        .callback = sysmon_timer_cb,
        .name = "sysmon_timer",
    };
    ESP_ERROR_CHECK(esp_timer_create(&timer_cfg, &s_mon_timer));
    ESP_ERROR_CHECK(esp_timer_start_periodic(s_mon_timer, interval_sec * 1000000ULL));
    return ESP_OK;
}
```

#### 4.2 关键指标采集代码

```c
void sysmon_print_status(void)
{
    // Memory info
    ESP_LOGI(TAG, "=== System Monitor Report ===");
    size_t free_heap = esp_free_heap_size();
    size_t min_heap = esp_get_minimum_free_heap_size();
    ESP_LOGI(TAG, "[Memory] Free: %zu B (%.1f%%), Min: %zu B",
             free_heap,
             free_heap * 100.0f / esp_get_total_heap_size(),
             min_heap);

    // PSRAM info
#if CONFIG_SPIRAM
    ESP_LOGI(TAG, "[PSRAM] Size: %d MB, Free: %zu KB",
             esp_psram_get_size() / (1024*1024),
             heap_caps_get_free_size(MALLOC_CAP_SPIRAM) / 1024);
#endif

    // Task info
#if CONFIG_EXAMPLE_SYSMON_PRINT_TASK_LIST
    char task_buf[512];
    vTaskList(task_buf);
    ESP_LOGI(TAG, "[Tasks]\n%s", task_buf);
#endif

    // Audio-specific metrics
    ESP_LOGI(TAG, "[Audio] Recorder state=%d, Player state=%d",
             recorder_get_state(), player_get_state());
}
```

#### 4.3 与音频模块的集成点

| 集成位置 | 监控动作 |

### 步骤5：性能基线与告警阈值

#### 5.1 预期性能基线

基于 ESP32-P4 的硬件规格，设定预期基线：

| 指标 | 正常范围 | 告警阈值 | 说明 |
|------|----------|----------|------|
| 堆内存使用率 | < 60% | > 85% | 总堆 320KB+SPIRAM |
| 录音任务栈水位 | > 50% 剩余 | < 20% 剩余 | 分配 4096 字节栈 |
| 播放任务栈水位 | > 50% 剩余 | < 20% 剩余 | 分配 4096 字节栈 |
| 录音 CPU 占用 | < 15% | > 25% | 仅 I2S 读取 + 文件写入 |
| 播放 CPU 占用 | < 35% | > 55% | 包含 Ogg 解码 |
| I2S DMA 溢出次数 | 0 | > 0/分钟 | 表示数据处理不及时 |

#### 5.2 告警机制设计

当指标超过阈值时，通过 ESP_LOGW 输出警告：

```c
#define WARN_THRESHOLD_HEAP_USAGE_PCT  85
#define WARN_THRESHOLD_STACK_HWM_PCT   20
#define WARN_THRESHOLD_CPU_USAGE       55

static void check_and_warn(const sysmon_report_t *report)
{
    // 堆内存告警
    if (report->heap_usage_pct >= WARN_THRESHOLD_HEAP_USAGE_PCT) {
        ESP_LOGW(TAG, "[WARN] Heap usage %.1f%% exceeds threshold!", report->heap_usage_pct);
    }
    // 栈水位告警（录音任务）
    if (report->recorder_stack_hwm_pct <= WARN_THRESHOLD_STACK_HWM_PCT) {
        ESP_LOGW(TAG, "[WARN] recorder stack HWM at %d%%", report->recorder_stack_hwm_pct);
    }
}
```

## 全局约束

- 系统监控模块为可选功能，通过 Kconfig 控制启用/禁用
- 监控日志不应影响实时音频处理性能
- 运行时统计功能会增加约 5-10% 的额外 CPU 开销
- 生产环境可降低日志频率或禁用详细任务列表
- 禁止直接修改 sdkconfig
