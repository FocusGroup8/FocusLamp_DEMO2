## 目标
建立麦克风录音→文件存储→Ogg解码播放的完整闭环测试系统，验证音频数据从采集到输出的端到端质量。

**承接上一步**：文档 `04-麦克风录音与功放播放方案.md` 完成了录音和播放模块设计，本文档验证这些模块协同工作时的完整性和可靠性。

## 阶段流程

### 步骤1：测试环境准备

#### 1.1 测试音频文件烧录

需要将示例 Ogg 音频文件预置到 LittleFS 分区中，方法有两种：

| 方案 | 操作方式 | 优缺点 |
|------|----------|--------|
| A: Flash 下载模式 | 使用 `esp_littlefs` 的 mklfs 工具打包镜像，随固件烧录 | 一键烧录，但每次更新文件需重新烧录 |
| B: 运行时写入 | 通过 UART/XMODEM 等协议在运行时传输文件到 LittleFS | 灵活，但需要额外传输代码 |

**推荐方案A**：使用 LittleFS 镜像打包方式，步骤：

1. 创建本地目录 `c:\Projects\Espressif_Projects\mipi_dsi\audio_files\`
2. 将示例 Ogg 文件（从 `example\music-sample\`）复制到该目录
3. 使用 `mklfs` 或 `esp_littlefs_partition_gen.py` 生成镜像：
   ```
   python <esp-idf-path>/components/spiffs/spiffsgen.py 0x180000 audio_files/ littlefs_image.bin
   ```
   > 注意：LittleFS 使用自己的镜像生成工具，需查证 esp_littlefs 组件是否提供了对应工具
4. 烧录镜像到 LittleFS 分区偏移地址：
   ```
   esptool.py --chip esp32p4 write_flash 0x310000 littlefs_image.bin
   ```

### 步骤2：I2S 全双工回环测试（Loopback）

#### 2.1 测试目标

验证 I2S 全双工通道能同时录音和播放。**注意**：完整的麦克风→文件→播放闭环尚无文件存储层支持，目前通过 I2S 测试套件验证底层驱动。

**当前已通过的测试**（详见 `03-I2S双工驱动实现方案.md`）：

| 测试项 | 函数 | 说明 | 结果 |
|--------|------|------|------|
| TX 正弦波输出 | `i2s_test_tx_sine_wave()` | 1kHz 正弦波 → MAX98357A | 通过 |
| RX 麦克风输入 | `i2s_test_rx_microphone()` | INMP441 → RMS 统计 | 通过 (RMS > 0) |
| 全双工同时读写 | `i2s_test_full_duplex()` | TX/RX 同时运行互不干扰 | 通过 |
| 回环诊断 | `i2s_test_loopback_diagnostic()` | DIN=DOUT 内部回环验证 | 99.8% 匹配 |

#### 2.3 已知风险与应对

| 风险 | 原因 | 应对 |
|------|------|------|
| 啸叫 | 麦克风和功放距离太近形成声反馈 | 增加物理距离、降低音量、使用 Acoustic Echo Cancellation |
| 延迟过大 | DMA 缓冲过多 | 减小 dma_buf_count 或 dma_buf_len |
| INMP441 数据全零 | 声道选择错误 | 检查 slot_mask 和 L/R 引脚 |
| MAX98357A 无声 | 数据通道错误 | 检查 DOUT GPIO 和声道配置 |

### 步骤3：录音→播放闭环测试（待开发）

> **注意**：以下测试流程依赖 LittleFS、WAV 录音模块、Ogg 播放模块，这些模块尚未实现。当前 I2S 驱动层已通过独立测试套件验证。

#### 3.1 测试流程（计划）

```
阶段1: 录音
  1. 挂载 LittleFS
  2. 初始化 I2S (16000Hz，当前已验证的采样率)
  3. 启动录音，录制 10 秒
  4. 停止录音，保存为 /audio/test_rec.wav

阶段2: 播放录音
  5. 读取 /audio/test_rec.wav（16000Hz WAV）
  6. 解码 PCM → I2S TX 输出
  7. 播放完毕

阶段3: 播放 Ogg 示例文件
  9. 读取 /audio/sample_opus.ogg
  10. 使用 esp_audio_codec 解码
  11. PCM 输出到 I2S TX
  12. 播放完毕
```

#### 3.2 测试验收标准

| 测试项 | 验收标准 |
|--------|----------|
| WAV 录音 | 文件大小正确（~938KB/30s@16000Hz/16bit/Mono） |
| WAV 播放 | 能回放录音内容，声音可辨识 |
| Ogg 播放 | 示例音乐文件正常解码播放 |
| 暂停/恢复 | 播放过程中暂停和恢复正常 |
| 音量控制 | 音量从0到100可调 |
| 文件管理 | 能列出 LittleFS 中的文件、查看剩余空间 |
| 存储空间 | 11.5MB 分区能容纳至少 4 条 30s WAV + 大量 Ogg |

#### 3.3 WAV 直接播放说明

由于 WAV 文件是 PCM 原始数据，无需解码器，可直接读取数据段并通过 I2S 输出：


### 步骤4：串口命令控制

用户已确认仅通过串口命令控制音频功能，不实现 GUI 界面。

#### 4.1 串口命令设计

基于 ESP-IDF 的 `esp_console` 组件或简单的串口解析实现以下命令：

| 命令 | 参数 | 功能 |
|------|------|------|
| `audio init` | 无 | 初始化音频系统（I2S + LittleFS） |
| `audio record` | [filename] [duration_s] | 开始录音（默认30秒） |
| `audio stop` | 无 | 停止录音/播放 |
| `audio play` | [filename] | 播放指定音频文件 |
| `audio pause` | 无 | 暂停播放 |
| `audio resume` | 无 | 恢复播放 |
| `audio volume` | [0-100] | 设置音量 |
| `audio list` | 无 | 列出 LittleFS 中的音频文件 |
| `audio status` | 无 | 显示当前音频系统状态 |
| `audio monitor` | [interval_s] | 启动/停止系统监控 |
| `audio deinit` | 无 | 反初始化音频系统 |
