## 操作

1. 编译并烧录 controller（COM6），head 不需要更新。重启桌面网页监听脚本。
2. 电脑和设备连接同一热点。网页选择真实设备、连接 controller，再手动恢复控制。
3. 在工作台的舵机控制下展开“逐轴点动标定”。
4. 选择从下往上的 1–5 号舵机，填写现场确认可试动的候选上下界、每步 raw，以及 LX 运动时间或 EM3 速度；这些输入没有安全默认值。勾选区间确认。
5. 点击“进入标定（只读参考）”。此步只读取所选轴当前位置，不发送运动命令。当前位置必须位于候选区间内，读失败或区间不符时不能点动。
6. 单击“＋ 一步”或“－ 一步”。一次只提交一步，不连发、不排队。每步先重新读取实际位置，再计算目标；目标超出候选区间就拒绝，不夹紧、不移动到边界。
7. 观察实物、实测 raw 和状态。记录方向及结构备注。点击“退出标定 / 软停止”，再导出候选标定记录 JSON。

候选区间必须来自机构资料与现场判断；当前位置及协议全行程都不能用来推算安全行程。灯头拆装会改变负载，最终整机仍需按实际装配验证。

## 行为

- 标定会话一次只占用一个轴；会话有效期间，固件拒绝普通动作、归位、语音动作和正式单轴入口。其他轴不发送运动命令。
- 正式五轴滑块继续受 `motion_manual_limits.h` 限制，当前范围见上表；标定会话有效时正式滑块仍锁定。
- 边界拒绝后可尝试反方向。读取失败、当前位置越出候选区间、发送失败或未确认到位后，需退出并重新进入标定。
- 到位确认使用选定轴的实际回读；`202 accepted` 只表示任务已受理，不表示已移动或到位。
- 退出、软件停止及重启使当前会话失效。不会自动恢复会话或重发旧目标。退出不自动返回参考位置。
- 软件停止取消未发送步骤并清队列；不能刹停舵机已经收到的运动，也不卸载扭矩。底层同步读取或写入需实际返回。
- JSON 导出包含参考位置、候选配置、已观察 raw 范围和备注。已观察范围不等于安全限位，导出不自动写固件。
- 原 `/api/arm/pose` 仍为空闲采样。本批没有完成运动中连续遥测或真实 3D 角度标定。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/arm/calibration` | 只读会话与反馈缓存，不查询 UART |
| POST | `/api/arm/calibration` | `action:begin` 登记候选配置并读取参考；`action:end` 退出指定会话 |
| POST | `/api/arm/jog` | 当前 `session_id` 配合 `direction:-1/1` 提交一步 |
| POST | `/api/arm/stop` | 既有软件停止，同时使标定会话失效 |

begin 必须显式包含 `servo_id/min/max/step/confirmed:true`，LX 另含 `time_ms`，EM3 另含 `speed`；不能混用。end 只包含 `action:end` 与 `session_id`。不提供自动试动脚本。
