## 目标
在 ESP32-P4 平台上实现基于 I2S 双工模式的麦克风录音-数字功放播放闭环音频系统，集成 LittleFS 文件系统存储和 Ogg 音频解码功能，并添加系统资源监控能力。

**任务范围**：本阶段仅完成方案与计划制定，不包含实际代码开发。
**不做什么**：不进行代码编写、不修改 sdkconfig、不执行编译烧录操作。

#### 1.3 Ogg 解码组件选型对比

通过 ESP Component Registry 搜索并对比以下三个候选组件：

##### 候选 A：espressif/esp_audio_codec (v2.6.0)

| 维度 | 详情 |
|------|------|
| 类型 | 官方统一编解码框架 |
| 支持格式 | 解码：Vorbis, Opus, MP3, AAC, WAV, FLAC, AMR, ALAC；编码：PCM, OPUS, AAC, ADPCM, G711 等 |
| API 特点 | 双层解码器 API（Simple Decoder 处理任意长度输入 + Decoder 处理帧边界数据） |
| 内存占用 | 轻量化优化，官方维护 |
| ESP32-P4 兼容性 | 官方支持，适配良好 |
| 缺点 | 组件较大（包含多种编解码器），需按需配置 |
| 适用场景 | 需要多格式支持或未来扩展性要求高时 |

##### 候选 B：esphome/micro-vorbis (v0.1.0)

| 维度 | 详情 |
|------|------|
| 类型 | 第三方专用解码器 |
| 支持格式 | 仅 Ogg Vorbis |
| API 特点 | C++ 流式解码，Arena 分配器减少堆分配，零拷贝 Ogg 解析 |
| 内存占用 | 低内存占用，PSRAM 支持 |
| ESP32-P4 兼容性 | 支持 RISC-V C fallback（P4 为 RISC-V 架构） |
| 缺点 | 仅支持 Vorbis 不支持 Opus，版本较新(v0.1.0)，稳定性待验证 |
| 适用场景 | 仅需 Vorbis 解码且对内存敏感时 |

##### 候选 C：esphome/micro-opus (v0.4.1)

| 维度 | 详情 |
|------|------|
| 类型 | 第三方专用解码器 |
| 支持格式 | 仅 Ogg Opus |
| API 特点 | C/C++ 流式解码，Xtensa DSP 优化（ESP32/S3），线程安全伪栈分配 |
| 内存占用 | PSRAM 可配置，伪栈 120KB+ per thread |
| ESP32-P4 兼容性 | 支持 Fixed-point（P4 为 RISC-V），但 Xtensa 优化不可用 |
| 缺点 | 仅支持 Opus，不支持 Vorbis/WAV；P4 上无 Xtensa 加速优势 |
| 适用场景 | 仅需 Opus 解码时 |

##### 选型建议矩阵

| 对比项 | esp_audio_codec | micro-vorbis | micro-opus |
|--------|-----------------|--------------|------------|
| 与示例音频匹配 | **支持** (Opus) | 不匹配 (仅Vorbis) | **完全匹配** (Opus) |
| 未来扩展性 | **优秀** | 差 | 差 |
| 官方维护 | 是 (Espressif) | 否 (Esphome) | 否 (Esphome) |
| 成熟度 | 高 (v2.6.0) | 中 (v0.1.0) | 中 (v0.4.1) |
| P4 RISC-V 优化 | 有 | 有 (C fallback) | 无 Xtensa 优势 |
| 组件体积 | 大 (多功能) | 小 (单一) | 小 (单一) |

> **确认闸门**：请确认 Ogg 解码组件的最终选择。推荐方案如下：
> - **首选方案**：`espressif/esp_audio_codec` — 官方统一编解码器，同时支持 Opus/Vorbis/WAV 解码和 PCM/OPUS 编码，与用户"录WAV播Ogg"需求完全契合，长期维护有保障
> - **备选方案**：`esphome/micro-opus` — 如果仅需 Opus 播放且追求最小化组件体积

#### 2.2 I2S 双工方案详细设计

##### 核心约束与决策依据

根据 ESP-IDF 官方文档（v5.x/v6.x），ESP32-P4 的关键特性：
- 包含 **3 个独立 I2S 外设**（I2S_NUM_0/1/2）
- 每个 I2S 控制器的 TX/RX 通道拥有 **独立的 MCLK、BCLK 和 GPIO**
- 通过 `i2s_new_channel()` 同时传入 `tx_handle` 和 `rx_handle` 即可启用 **全双工模式**

**方案选择：单控制器全双工模式（推荐）**

选择原因：
1. 麦克风和功放共用 BCLK(32)/LRC(33)，天然适合同一 I2S 控制器
2. 全双工模式下时钟同步，避免采样率偏差导致的回声/失真
3. 减少一个 I2S 控制器占用，保留给未来扩展
4. 录放闭环测试需要严格的时序同步

##### I2S 配置参数

```
I2S 控制器: I2S_NUM_0 (可配置为 I2S_NUM_AUTO 自动分配)
工作角色: I2S_ROLE_MASTER (ESP32-P4 作为主机提供时钟)
通信模式: I2S_COMM_STD_PHILIPS (Philips 标准 I2S 格式)
采样率: 16000 Hz (当前测试阶段使用，后续可按需调整)
位宽: I2S_DATA_BIT_WIDTH_32BIT (INMP441 输出24-bit左对齐在32-bit帧中，必须用32-bit)
声道: 单声道 MONO + LEFT slot
槽位模式: I2S_SLOT_MODE_MONO
slot_mask: I2S_STD_SLOT_LEFT (INMP441 L/R=GND 输出左声道，功放亦输出左声道)
格式: Philips (I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG)
MCLK 倍数: I2S_MCLK_MULTIPLE_256 (MCLK 未使用，此值不影响)
DMA 缓冲: dma_buf_count=16, dma_buf_len=960 (经验证的值)
```

##### GPIO 引脚映射表

| I2S 信号 | GPIO | 连接设备 | 方向 | 说明 |
|----------|------|----------|------|------|
| MCLK | - | 未使用 | 输出 | 可选，INMP441/MAX98357A 不需要 |
| BCLK | GPIO32 | 共享 (INMP441 + MAX98357A) | 输出 | 位时钟 |
| WS/LRC | GPIO33 | 共享 (INMP441 + MAX98357A) | 输出 | 字选择/左右声道 |
| DOUT | GPIO31 | MAX98357A DIN | 输出 | 功放数据输入 |
| DIN | GPIO30 | INMP441 SD | 输入 | 麦克风数据输出 |

##### 初始化流程

```
1. i2s_new_channel() → 创建 tx_handle + rx_handle (全双工)
2. 配置 i2s_std_config_t（共享配置，同时指定 dout 和 din）
   - slot_cfg: I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_32BIT, I2S_SLOT_MODE_MONO)
   - slot_mask: I2S_STD_SLOT_LEFT
   - gpio_cfg: bclk=32, ws=33, dout=31, din=30
3. i2s_channel_init_std_mode(tx_handle, &std_cfg) → TX 通道
4. i2s_channel_init_std_mode(rx_handle, &std_cfg) → RX 通道（使用同一配置）
5. i2s_channel_preload_data(tx_handle, ...) → 预加载 DMA 缓冲区
6. i2s_channel_enable(tx_handle) / i2s_channel_enable(rx_handle)
7. vTaskDelay(100ms) → 等待 I2S 外设稳定
```

#### 2.3 存储子系统设计

##### 分区表方案

需要自定义分区表以支持 LittleFS 文件系统：

```csv
# Name,   Type, SubType, Offset,     Size,      Flags
nvs,      data, nvs,     ,           0x6000,
phy_init, data, phy,     ,           0x1000,
factory,  app,  factory, ,           0x400000,  # 4MB 应用程序 (16MB Flash)
littlefs, data, spiffs,  ,           0xB80000,  # 11.5MB LittleFS 音频存储区
```

**存储容量计算**（录音 30 秒，16000 Hz 采样率，16bit 单声道 WAV）：
- 原始 PCM 数据量：16000 samples/s * 2 bytes * 30s = 960,000 bytes ≈ 0.92 MB
- WAV 文件头：44 bytes
- 单次录音总大小：约 0.92 MB
- 11.5MB 分区可容纳：~12 条 30s 录音 + 大量 Ogg 播放文件

##### LittleFS 配置要点

- 使用 ESP-IDF 内置的 `esp_littlefs` 组件
- 通过 menuconfig 启用：Component config -> LittleFS
- 挂载路径建议：`/audio`
- 文件命名规范：`recording_xxx.wav`, `music_xxx.ogg`

#### 2.4 音频数据处理流水线

##### 当前完成的测试流水线（I2S 双工驱动验证）

```
[I2S TX] → [DMA预加载] → [1kHz正弦波] → [I2S DOUT GPIO31] → [MAX98357A]
    ↓ 全双工共享 BCLK/WS
[I2S RX] → [DMA读取] → [32-bit样本] → [幅值统计/RMS计算] ← [INMP441 GPIO30]
```
