> 本文档面向接手 FocusLamp 算法端工作的开发者，覆盖 DEMO1 与 DEMO2 两个 Demo 的整体介绍、版本关系、代码结构、模块索引、负责人、详细文档链接、仓库与目录对应关系、开源依赖及整体运行流程。
>
> 生成日期：2026-09-29

## 1. DEMO1 / DEMO2 整体介绍及版本关系

### 1.1 两个 Demo 是什么

FocusLamp 是一个「专注灯」系统：由 **ESP32-P4 灯头板** 采集摄像头画面（或由 PC 本地摄像头替代），把画面推送给 **PC 端算法服务**，算法服务完成人脸/情绪/疲劳/专注度/姿态/手势/玩游戏等检测后，把结果回传，用于驱动灯具的表情、灯光、机械臂与语音反馈。

算法端（本交接范围）由两个 Demo 工程组成：

| Demo | 定位 | 算法服务数量 | 技术形态 |
|------|------|--------------|----------|
| **DEMO1** | 第一版算法端，验证"多算法微服务 + Web 可视化"链路 | 6 个算法服务 | Docker Compose 微服务 |
| **DEMO2** | 第二版算法端，扩展算法能力并打通"算法端 → ESP32"结果回传协议 | 12 个算法服务 + 1 个单机版检测器 | Docker Compose 微服务 + 单机 Python 工程 |

### 1.2 版本关系（DEMO1 → DEMO2 的演进）

DEMO2 是在 DEMO1 基础上演进而来，主要变化：

1. **算法服务扩充**：DEMO1 的 6 个算法（head-pose、gesture、focus、emotion、fatigue、face-detector）在 DEMO2 中扩展为 12 个。
   - 新增：`gesture-mantis`（MediaPipe 手势 + 组合手势）、`pose-detector`（姿态 + 颈部运动）、`face-landmarker`（人脸网格）、`face-position`（面部空间坐标）、`vlm-visual-qa`（豆包 VLM 视觉问答）、`vlm-game-detector`（YOLO + 手部接触 + 豆包 VLM 判定玩游戏）。
   - 重写：`focus` 由「YOLO + MediaPipe FaceMesh」改为「Mantis/engage ONNX + MediaPipe 五官/手势 + 番茄钟管理」。
   - 保留为遗留参考实现（DEMO2 未在 docker-compose 中启用）：`gesture`、`head-pose`。
2. **通信协议升级（关键差异）**：DEMO1 算法结果仅在 PC 端本地消费；DEMO2 新增 ESP32 `/algo` WebSocket 通道，算法结果以 **JSON-RPC 2.0 `tools.call` / `algorithm.result`** 形式回传给灯头板。
3. **摄像头帧协议补全**：ESP32 `/camera` 端点每帧先发 `{"type":"frame_header","seq":N}` 文本帧，再发二进制 JPEG，算法端据此做丢帧/乱序检测。
4. **新增单机版工程**：`algorithm/FocusDetector`（v0.2.0），不依赖 Docker 与 ESP32，直接在 PC 上跑本地摄像头做专注/行为检测演示与算法验证。
5. **工程健壮性增强**：DEMO2 的 docker-compose 增加健康检查、日志轮转、内存/CPU 限制、tmpfs、`profiles` 等生产化配置；算法新增忙碌跳过（503）、skip_frames 降频、forced_algorithms 强制启用等机制。

> 版本关系的判断依据：两个工程的 `docker-compose.yml`、`README.md`、`KNOWLEDGE_BASE.md` 与算法服务实现互相对应，DEMO2 是 DEMO1 的超集与协议升级版。

## 2. 项目代码结构和各模块索引

### 2.1 DEMO2 代码结构

工程根目录：`d:\Docker`

```
d:\Docker\
├── docker\                          # 算法微服务工程（Docker Compose）
│   ├── docker-compose.yml           # 服务编排（端口、环境变量、健康检查、资源限制）
│   ├── .env                         # 密钥文件（ARK_API_KEY，禁止提交）
│   ├── .env.example                 # 密钥模板
│   ├── README.md                    # 工程总说明与 Docker 使用指南
│   ├── KNOWLEDGE_BASE.md            # 问题与解决方案知识库
│   ├── 算法接口文档.md               # 算法服务接口契约
│   ├── start.bat / start-camera.bat # Windows 启动脚本
│   ├── main-client\                 # 主控客户端（Web UI + 算法调度 + 结果回传）
│   ├── camera-capture\              # 本地摄像头采集服务（WebSocket 广播 JPEG）
│   └── algorithms\                  # 算法微服务集合
│       ├── _common\                 # 公共工具（图像编解码、中文字体绘制）
│       ├── focus\                   # 专注度/参与度（9003）
│       ├── emotion\                 # 情绪识别（9004）
│       ├── fatigue\                 # 疲劳检测（9005）
│       ├── face-detector\           # 人脸检测（9006）
│       ├── gesture-mantis\          # 手势识别（9009）
│       ├── pose-detector\           # 姿态 + 颈部运动（9010）
│       ├── face-landmarker\         # 人脸网格（9011）
│       ├── face-position\           # 面部空间坐标（9012）
│       ├── vlm-visual-qa\           # 豆包 VLM 视觉问答（9013）
│       ├── vlm-game-detector\       # 玩游戏检测（9014）
│       ├── gesture\                 # 遗留：手势关键点（9002，未启用）
│       └── head-pose\               # 遗留：头部姿态（9001，未启用）
├── algorithm\
│   └── FocusDetector\               # 单机版专注检测器（非容器，v0.2.0）
└── docs\                            # 交接文档（本文档所在目录）
```

> 说明：`ESP32P4C5\` 目录为开发阶段用于了解 ESP 端代码而引入的固件工程，**不属于本次算法端交接范围**，也不纳入仓库提交。

- `.env`（含真实 `ARK_API_KEY`）**不提交**，仅提交 `.env.example` 模板；部署时需自行创建 `.env` 并填写密钥。

- 构建产物与生成物不提交：`__pycache__/`、`managed_components/`、`build/`、`*.pyc`、日志与临时文件。
- `ESP32P4C5/` 固件工程**不提交**（不属于算法端交接范围）。

## 7. 两个 Demo 的整体运行流程

### 7.1 DEMO1 运行流程

```
[ESP32-P4 灯头板 :8080 /camera]  ──(或──  [本地 USB 摄像头 → camera-capture :9007])
                │  WebSocket 二进制 JPEG 帧
                ▼
        [main-client :9000]  ── 逐帧调度，POST /detect_visualize (base64 图像)
                │
                ├──► head-pose-detector :9001   → yaw/pitch/roll, face_x/face_y
                ├──► gesture-detector   :9002   → 手势类型 type, confidence
                ├──► focus-detector     :9003   → 专注度（YOLO + FaceMesh）
                ├──► emotion-detector   :9004   → 情绪类别, rating
                ├──► fatigue-detector   :9005   → 眨眼/哈欠/点头
                └──► face-detector      :9006   → 人脸 bbox + 关键点
                │
                ▼
   [main-client Web UI  (http://localhost:9000)] 展示各算法可视化结果
```

要点：
- 算法结果仅在 PC 端消费（Web 可视化），未回传 ESP32。
- 各算法服务均发布宿主机端口（9001–9006），便于单服务调试（`curl http://localhost:9001/health`）。
- `camera-capture` 在 docker-compose 中标记 `profiles: camera`，默认不随 `up -d` 启动，需 `docker-compose --profile camera up -d`。

### 7.2 DEMO2 运行流程

```
[ESP32-P4 灯头板  :80]
   ├─ /camera ──► 文本帧 {"type":"frame_header","seq":N}  +  二进制帧 JPEG
   │                        │
   │                        ▼
   │              [main-client :9000]  ←──(或──  camera-capture :9007 本地摄像头)
   │                        │
   │                        ├─ 解码 JPEG、按 skip_frames 调度
   │                        ▼  POST /detect_visualize (base64 + timestamp)
   │          ┌─────────────┴───────────────────────────────────────┐
   │          │ focus 9003 · emotion 9004 · fatigue 9005 · face-detector 9006 │
   │          │ gesture-mantis 9009 · pose 9010 · face-landmarker 9011│
   │          │ face-position 9012 · vlm-visual-qa 9013 · vlm-game-detector 9014 │
   │          └─────────────┬───────────────────────────────────────┘
   │                        │  result 子对象 + visualized_image
   │                        ▼
   │              [main-client Web UI  http://localhost:9000] 展示可视化
   │                        │
   └── /algo ◄──────────────┘  JSON-RPC 2.0 tools.call → algorithm.result
                               （每 ALGO_SEND_INTERVAL 默认 1.0s 回传一次）
```

**算法结果回传（`/algo`）协议要点**

- 算法端 → ESP32（请求）：

```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools.call",
  "params": {
    "name": "algorithm.result",
    "arguments": {
      "focus": {"engage_level_name": "Engaged", "focus_level_name": "HighFocused", "focus_score": 0.85},
      "emotion": "happiness",
      "fatigue": 2,
      "gesture": "Thumb_Up",
      "vlm_game_detector": {"judgment": "是", "trigger_source": "phone", "reason": "..."},
      "presence": {"present": true, "duration_s": 65.0}
    }
  }
}
```

- ESP32 → 算法端（响应）：

```json
{ "jsonrpc": "2.0", "id": 42, "result": { "content": [{"type": "text", "text": "{\"ok\":true}"}], "isError": false } }
```

- `frame_header` 不含 `timestamp` 字段（ESP32 未集成 SNTP），算法端在字段缺失时回退使用本机 Unix 时间戳。详见 [ESP32通信协议修复同步.md](../ESP32通信协议修复同步.md)。
- `vlm_game_detector.trigger_source` 在算法端代码中的实际取值为英文 `phone` / `computer`；`judgment` 由豆包 API 返回（未触发时为 `pending`）。历史上该字段曾约定为中文 `手机` / `电脑`，如需改回中文需与硬件端共同确认并修订协议文档。
