云端短欢迎语（2026-10-31）

本批范围
只改拍头欢迎语及网页“下一条欢迎语”。雷达久坐提醒仍用现有本地 WAV。
head 仍发送三条原触发文字；controller 收到后转换为九条“请只朗读：…”短指令。
只需重新编译/烧录 controller（COM6），head 不需要重烧。分区表、原 WAV、音色、SDK 均不变。
网页后台也需要重新启动并强制刷新页面，仅刷新浏览器不能重新加载后台模块。

行为
九条已验证的短指令按 1→9→1 循环，整条含前缀及标点均少于15个字符。
每次成功受理后前进一条，重启从第1条开始；被跳过的不前进，已受理后超时的不补播。
普通对话、本地音频、其他云端播报或重连期间，本次拍头播报跳过，不长期排队。
入队与真正取得会话之间再次核查；若出现竞争，worker 跳过这次欢迎语。
云端30秒未启动则超时，不自动改播旧录音、不自动重发云端文字。
长按仍经 /api/chat/end 取消待播/当前播报，并保留原来的收尾逻辑。
头灯、表情、机械臂拍头动作未改。head 原有 HTTP 网络重试逻辑未改；
本批“不重发”指 controller 不重试已提交的云端播报，不保证跨网络超时的 HTTP 恰好一次。

配置
不需要改模型、语速、音色ID、MCP、唤醒词、设备绑定或网络参数。
保留各角色的人设正文和“忽略 FbCkS 等唤醒字符”的段落。
将云端原“核心规则：预设播报指令”整个段落替换成下面这段公共规则。
本文件不包含授权，不会自动写入云端配置；八个角色使用同一公共规则。
不要再用欢迎语1/2/3映射出“主人/Focus”的旧长文案，新的拍头路径不使用这些编号指令。

## 核心规则：预设播报指令

当输入以“请只朗读：”开头时，这是设备发起的固定播报指令。
只朗读该前缀后面的文字，保持当前角色已配置的音色。
不要朗读“请只朗读”这几个字，不改写、不扩写、不追加问候、自称或行动建议。
不要追问、反问、调用工具、创建任务或设置提醒与计时器。
此时不套用角色通常对话中的“先确认目标、再检查、再行动”等步骤，直接读出指定正文。
不要把这次指令或播报描述成真实的传感器观察或已经完成的操作。

兼容原设备指令：
- 提醒我休息 → 你已经坐了一会儿，站起来活动一下吧。
- 久坐提醒 → 你已经坐了一会儿，起来走动一下吧。
- 提醒我调整坐姿 → 调整一下坐姿，让肩膀放松一点吧。
- 提醒我集中注意力 → 我们先回到眼前这一小步吧。
- 提醒我喝水 → 喝口水，稍微放松一下吧。
- 玩手机提醒 → 先放下手机，回到眼前这一件事吧。
- 玩电脑提醒 → 先停下游戏，起来活动一下吧。
对上述兼容指令，只播报对应文字，不追问、不创建任务或设置计时器。
--- 可复制的公共规则结束 ---

验收
1. 上电等待基座连接；不先喊唤醒词。拍头一次，应出现 Cloud welcome 1/9 accepted。
2. 从请求到云端 TTS START/STOP、cleanup outcome=1，再拍下一次；依次听完9条后回到第1条。
3. 等待或播报期间连续拍击，应记录 skipped，不在稍后连续补播。
4. 先进行正常对话再拍头：灯光和表情仍响应，欢迎语跳过，不打断对话。
5. 长按取消后，确认唤醒恢复；下次空闲时可正常拍头。
6. 网页启用另一个角色、结束旧会话，再拍头听辨音色；文字里的角色名不是音色证明。
7. 雷达提醒仍为原本地录音，声音不会在本批跟随云端角色切换。
